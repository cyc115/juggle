### 1. Apply the dogfood DB snapshot fix (carryover — 4th week)

**File: `src/schedules/dogfood.py`, lines 45–70 (`TASK_PROMPT_TEMPLATE`) and line 290 (`run()` function)**

The fix: before calling `_run_headless_research`, extract live DB data and embed it in the prompt. This is a 25–30 line addition:

```python
# In run(), before task_prompt = TASK_PROMPT_TEMPLATE.format(...)
db_snapshot = _extract_db_snapshot(db, since_date)
task_prompt = TASK_PROMPT_TEMPLATE.format(since_date=since_date, db_snapshot=db_snapshot)
```

`_extract_db_snapshot(db, since_date)` should query `nodes`, `agent_completions`, `watchdog_events`, and `action_items` for the window and return a compact markdown block (≤2000 chars). Embed `{db_snapshot}` in `TASK_PROMPT_TEMPLATE` between the analysis instructions and the output-format requirement. Without this fix, the dogfood routine cannot analyze real thread-level data in the cloud execution context.

### 2. Add a pre-wiring gate for new watchdog sweeps

**File: `tests/test_async_reclassify.py` (reference) + new test pattern in `tests/test_watchdog_sweeps.py`**

New sweeps are being wired into `juggle_watchdog_daemon.py` and `juggle_watchdog_sweeps.py` before their edge-case coverage is complete. After the reclassify sweep landed, three bug fixes followed within hours. A pre-wiring gate for all new sweeps should require, at minimum, tests for: (a) the zero-candidates case, (b) the all-junk candidates case, (c) the decision-apply failure case, and (d) the import path for any helper it calls.

This is a checklist addition to `CLAUDE.md` or a required test fixture in `tests/conftest.py` that gates wiring via a `@pytest.mark.sweep_integration` marker that must be green before `wire into tick` commits land. Cost: ~1 hour to document, zero runtime overhead.

---

### 3. Harden graph mutation entry points against unguarded node kinds

**File: `src/juggle_cmd_graph_cancel.py` (reference fix at `dc1700a`) + audit of `src/juggle_cmd_graph_*.py`**

`cancel-node` crashed on topic nodes because the entry point lacked a kind-check. The same gap may exist in other graph mutation commands (`graph edit`, `graph add`, `graph show`). A quick audit: grep all `juggle_cmd_graph_*.py` for direct `nodes` table mutations and verify each has an explicit `kind` guard before the mutation. If any are missing, add a single shared `_assert_mutable_kind(node)` helper in `juggle_cmd_graph_ops.py` that all mutation entry points call. This prevents the next variant of this crash from reaching production.
