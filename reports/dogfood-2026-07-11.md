## Suggested Improvements (1–3)

**1. Pre-extract DB snapshot into the prompt before calling `claude -p`**
`_run_headless_research` passes a free-text prompt telling the agent to query the DB
itself (`"Review the last 7 days of completed threads in the Juggle SQLite DB"`).
This breaks in any environment where the DB file is outside the agent's permission
scope. Fix: extract the data in Python before spawning the agent, then embed the
snapshot in the prompt. The agent should analyze data, not discover it.

File: `src/schedules/dogfood.py:45–70` (`TASK_PROMPT_TEMPLATE`) and
`src/schedules/dogfood.py:119–161` (`_run_headless_research`).

Suggested fix sketch:
```python
# In run(), before building task_prompt:
db_snapshot = _extract_db_snapshot(db, since_date)  # new helper, pure SQL
task_prompt = TASK_PROMPT_TEMPLATE.format(since_date=since_date, db_snapshot=db_snapshot)
```
The template includes `{db_snapshot}` as a pre-rendered table of counts and rows. The
agent receives data, not a file-path instruction.

**2. Add a cloud-environment guard that reports "no local DB" instead of running blind**
When the DB was freshly initialized this session (no rows in `nodes` or `agent_runs`),
the routine should emit a `[NO-LOCAL-DB]` action item and exit early rather than
spending $0.15 on an agent that produces an empty or invalid report.

File: `src/schedules/dogfood.py:290–380` (`run()`) — add after `get_db()`:
```python
if _db_is_fresh(db):  # helper: nodes+agent_runs both empty
    _file_action_item(db, "[NO-LOCAL-DB] Cloud container has empty DB — "
                      "run dogfood locally against production DB.", None, dry_run)
    return 0
```

**3. Normalize timestamp columns across operational tables**
`error_events` (`first_seen`/`last_seen`), `agent_runs` (`dispatched_at`/`completed_at`),
and `watchdog_events` (`created_at`) use different column names for the creation
timestamp. Any cross-table date-window query must handle each table specially.
Add a `created_at` generated column aliasing the canonical timestamp per table, or
add it as a real column in the next migration via `dbops/migration_seq.py`.

File refs:
- `src/dbops/schema_selfheal.py` — `error_events` DDL
- `src/dbops/schema_runs.py` — `agent_runs` DDL
